# الخطة والمعمارية التفصيلية — Codera

> منصّة SaaS وايت-ليبل لتجربة اللبس الافتراضية بالذكاء الاصطناعي، تُباع للمتاجر باشتراك شهري.

---

## 1. الرؤية والنموذج التجاري

- **أنتِ (Codera):** تملكين المنصّة والموديلات ومحرّك الذكاء الاصطناعي.
- **العميلة (التاجر):** صاحبة متجر ملابس. تشترك شهرياً، ترفع/تستورد منتجاتها، وتظهر
  التجربة الافتراضية على متجرها **بدومينها الخاص** ودون ظهور اسم شركتك (white-label).
- **الزائرة (المتسوّقة):** تختار قطعة، تشوفها على موديل يشبهها (أو على صورتها)، فتزيد ثقتها بالشراء.

**مصدر الدخل:** اشتراكات شهرية بحصص توليد (Freemium/Tiered). تكلفتك الأساسية = استدعاءات
محرّك الـ AI + التخزين + الاستضافة. الربح = فرق الاشتراك عن هذه التكلفة.

## 2. المعمارية العامة (multi-tenant)

```
                     ┌─────────────────────────────────────────┐
                     │              Codera Platform             │
   دومين المتجر  ───▶│  توجيه حسب Host → تحديد المستأجر (tenant) │
 shop.client.com     │                                          │
 noor.codera.app     │  ┌────────────┐  ┌───────────────────┐   │
                     │  │  Storefront │  │  Merchant Dashboard│   │
   app.codera.app ──▶│  │  (الزوّار)   │  │   (التاجر)         │   │
                     │  └─────┬──────┘  └─────────┬─────────┘   │
                     │        │                   │             │
                     │  ┌─────▼───────────────────▼─────────┐   │
                     │  │           REST API                 │   │
                     │  └─┬────────┬─────────┬──────────┬───┘   │
                     │    │        │         │          │       │
                     │  ┌─▼──┐  ┌──▼───┐  ┌──▼────┐  ┌──▼────┐  │
                     │  │ DB │  │  AI   │  │Shopify│  │Billing│  │
                     │  │    │  │providers│ │import │  │UPay.. │  │
                     │  └────┘  └──┬────┘  └───────┘  └───────┘  │
                     └────────────┼────────────────────────────┘
                                  ▼
                    FASHN / Replicate / (Mock offline)
```

### تحديد المستأجر (Tenant Resolution)
`src/lib/tenant.js` يحدّد المتجر من ترويسة `Host`:
1. **دومين خاص** مطابق لـ `tenants.custom_domain` → `shop.client.com`
2. **نطاق فرعي** من `BASE_DOMAIN` → `{slug}.codera.app`
3. **?tenant=slug** للاختبار المحلي على `localhost`

> **الدومين الخاص:** العميلة توجّه `CNAME` من دومينها إلى منصّة Codera، ونحفظ الدومين في
> `tenants.custom_domain`. TLS تلقائي عبر عكسي (Caddy/Traefik) مع Let's Encrypt On-Demand.

## 3. طبقة البيانات (SQLite الآن · PostgreSQL للإنتاج)

الجداول الأساسية (`src/db/schema.sql`):

- `tenants` — المتاجر (اسم، slug، custom_domain، الباقة، الحالة، هوية العلامة)
- `users` — مستخدمو كل متجر (owner/staff)
- `plans` / `subscriptions` — الباقات والاشتراكات
- `house_models` — موديلات Codera العامة (إثنية، بشرة، **حجاب**، وضعيات، صورة)
- `tenant_models` — الموديلات المفعّلة لكل متجر
- `products` — المنتجات (مصدرها manual/shopify، الفئة، صورة القطعة للتجربة)
- `tryon_jobs` — وظائف التوليد (طابور → معالجة → نتيجة)
- `usage_events` — عدّاد الاستهلاك الشهري (للحصص والفوترة)
- `import_jobs` / `shopify_connections` — الاستيراد وربط شوبيفاي

> **الترحيل للإنتاج:** المخطط SQL قياسي. الانتقال إلى Postgres = تبديل طبقة `src/db/index.js`
> فقط (نفس الاستعلامات تقريباً) + استخدام مزوّد مُدار (Supabase/Neon/RDS).

## 4. محرّك الذكاء الاصطناعي (طبقة قابلة للتبديل)

`src/services/ai/` — واجهة موحّدة `TryOnProvider.generate(input)`:

| المزوّد | الملف | ملاحظات |
|---|---|---|
| **Mock** | `mock.js` | يعمل بدون مفاتيح — يولّد معاينة توضيحية (للتطوير/العرض) |
| **FASHN** | `fashn.js` | مخصّص لتجربة لبس الملابس (tops/bottoms/one-pieces) — **موصى به** |
| **Replicate** | `replicate.js` | نماذج مفتوحة مثل IDM-VTON (تحكّم أكبر بالتكلفة) |

**المدخلات:** صورة القطعة (flat-lay) + صورة الموديل (أو صورة العميلة) + الفئة + الحجاب + الوضعية.
**التبديل:** متغيّر `AI_PROVIDER` فقط. إضافة مزوّد جديد = ملف واحد يطبّق الواجهة.

**تدفّق التوليد:** POST `/api/tryon` ينشئ وظيفة `queued` ويردّ فوراً → عامل داخلي
(`setImmediate`) يعالجها → الواجهة تستعلم عن الحالة حتى `done`. في الإنتاج يُستبدل العامل
الداخلي بطابور حقيقي (BullMQ/Redis) لتحمّل الضغط.

### الموديلات الخاصة + الحجاب
`house_models` تحتوي موديلات بمواصفات متنوعة (خليجي، جنوب آسيوي، بشرة داكنة...) وحقل `hijab`.
لإنتاج موديلات ثابتة الهوية (نفس الوجه في كل الصور) يُنصح بتدريب/تثبيت مرجع لكل موديل
(reference image + seed ثابت، أو LoRA لكل شخصية) — انظر خارطة الطريق.

## 5. ترحيل بيانات شوبيفاي

`src/services/shopify/importer.js` — طريقتان:
1. **API:** برمز تطبيق مخصّص (`shpat_...`) نسحب `products.json` ونحوّلها لمنتجات Codera.
2. **CSV:** ملف تصدير شوبيفاي القياسي (نجمع الصفوف حسب `Handle`).

نستنتج فئة القطعة تلقائياً (عباية/فستان/علوي/سفلي/إكسسوار) من النوع/الوسوم/العنوان.
التفاصيل في [`SHOPIFY_MIGRATION.md`](SHOPIFY_MIGRATION.md).

## 6. الاشتراكات والفوترة

`src/services/billing/` — خطط بحصص شهرية (`quota_month`) + تتبّع استهلاك + محوّل **UPayment**.
قبل كل توليد نتحقق من الحصة (402 عند التجاوز). التوصية الكاملة ومقارنة البدائل الأوفر في
[`PRICING.md`](PRICING.md).

## 7. الأمان

- كلمات المرور: `scrypt` بملح لكل مستخدم.
- الجلسات: توكن عشوائي + كوكي `HttpOnly` + `SameSite=Lax`.
- العزل بين المستأجرين: كل استعلام مقيّد بـ `tenant_id`؛ الجلسة تحمل `tenant_id`.
- رفع الصور: base64 مُحقّق النوع، تُخزّن خارج مسار الكود.
- **للإنتاج:** أضِف تحديد معدّل (rate-limit) على `/api/tryon`، فحص محتوى الصور، و CSP للودجت.

---

## 8. النشر

- **الحاوية:** `node --experimental-sqlite src/server.js` خلف عكسي (Caddy) للـ TLS/الدومينات.
- **الدومينات الخاصة:** Caddy On-Demand TLS يصدر شهادة لأي دومين مسجّل في `tenants`.
- **التوسّع:** انقل الحالة إلى Postgres + Redis (طابور) + تخزين كائنات (S3/R2) للصور،
  وشغّل عدة نسخ خلف موازن حِمل.

## 9. حدود الـ MVP الحالية (يجب تطويرها للإنتاج)

- SQLite ملف محلي (مناسب للتطوير، ليس للتوسّع الأفقي).
- عامل التوليد داخل العملية (بدون طابور موزّع/إعادة محاولة).
- الدفع المتكرر يحتاج جدولة فوترة دورية (cron) — الأساس موجود، انظر PRICING.
- الموديلات ثابتة الهوية تحتاج إعداداً إضافياً على مستوى نموذج الصور.
